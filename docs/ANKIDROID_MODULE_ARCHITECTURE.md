# ANKIDROID_MODULE_ARCHITECTURE — AnkiDroid Connect モジュール設計書

> **状態:** 設計確定（Entei Modules 傘下モジュール統合 / 最終承認確定版）  
> **対象:** Android版 Entei における AnkiDroid Connect 連携、`plugins/tauri-plugin-modules`（Entei Modules）配下への組み込み、ContentProvider 通信、メディア登録、統一モジュール API  
> **方針:** アプリ直結の個別プラグインを新設するのではなく、Entei プラットフォームの統一プラグインである **`plugins/tauri-plugin-modules`（Entei Modules）の配下** に AnkiDroid Connect をモジュールとして統合する。フロントエンド（`tauri-bridge.ts`）で Android 環境を検知した際は Entei Modules の統一エンドポイント（`plugin:modules|modules_ankidroid_*`）を経由して通信し、Android 環境下で AnkiDroid 公式の ContentProvider API（`FlashCardsContract` / `AddContentApi`）へプロセス間直結する。

---

## 1. 概要とアーキテクチャ階層

### 1.1 階層構造（完全統一モジュールパイプライン）
すべてのモジュール機能（YouTube, Torrent, Yomitan, Jimaku, Nadeshiko）と同様に、AnkiDroid Connect も **Entei Modules (Tauri Plugin)** の傘下で管理される：

```text
[ フロントエンド (React / TypeScript: PlayerApp / Yomitan / 設定画面) ]
                     │
                     ▼
             tauri-bridge.ts (透過ルーティング: isAndroid() 判定)
                     │
                     ├─ [デスクトップ (Windows / Mac / Linux)]
                     │     └─ plugin:anki|anki_request (127.0.0.1:8765) ──► 公式 AnkiConnect
                     │
                     └─ [モバイル (Android)]
                           └─ plugin:modules|modules_ankidroid_request
                                 │
                                 ▼
[ Entei Modules プラグイン (plugins/tauri-plugin-modules) ]
  ├─ 🎬 ytdlp      (YouTube ストリーム取得)
  ├─ 🧲 torrent    (Magnet/Torrent P2P ストリーミング)
  ├─ 📖 yomitan    (辞書エンジン・Dexie バックアップ)
  ├─ 💬 jimaku     (字幕検索 API)
  ├─ 🧠 nadeshiko  (例文検索 API)
  └─ 📱 ankidroid  (AnkiDroid Connect モジュール / Android 専用) ★ここ！
                     │
                     ▼ run_mobile_plugin_async (Kotlin JNI)
        [ AnkiDroidModule.kt (@TauriPlugin) ]
          ├─ DeckApi (デッキ一覧・ID逆引き)
          ├─ ModelApi (ノートタイプ・フィールド定義・MID/名前解決)
          ├─ NoteApi (カード追加・差分マージ更新・重複判定)
          ├─ CardApi (10進合成カードID / cardsInfo / findCards / suspend 解決)
          └─ MediaApi (FileProvider メディア受け渡し)
                     │
                     ▼ (Android ContentProvider IPC)
        [ AnkiDroid アプリ本体 (com.ichi2.anki) ]
          └─ FlashCardsContract (内部 SQLite へ即時反映)
```

### 1.2 なぜ「Entei Modules の配下」にするのか？
1. **プラットフォーム統一と高凝集・疎結合**:
   - アプリ側から見ると、拡張機能への窓口は常に単一の **`tauri-plugin-modules`（Entei Modules）** だけになる。
   - 個別のプラグイン（`tauri-plugin-ankidroid` 等）を乱立させず、IPC コマンドのネームスペースも `plugin:modules|modules_ankidroid_*` に一本化される。
2. **モジュール管理画面（`/settings/?group=module`）とのシームレスな統合**:
   - 将来的に `ankidroid.module.json` を配置することで、Entei Modules のモジュール棚・設定画面へも他モジュールと全く同じ規格で並べることができる（※マニフェスト化は後のフェーズで実施）。
3. **外部 APK ＆ HTTP サーバー（ポート8765）の完全排除**:
   - AnkiDroid 公式の `AddContentApi` を Entei Modules の Android 依存として組み込むため、スマホ内で HTTP サーバーを一切立ち上げず、OS 標準の `ContentResolver` で超高速・省電力に直結する。

### 2.3 build.rs と Tauri v2 モジュールハンドシェイク
`plugins/tauri-plugin-modules/build.rs` で Android パスと新コマンドを設定：

Rust 側と Kotlin 側のクラス解決が完全一致するよう、`ANKIDROID_IDENTIFIER` を Kotlin のパッケージ名と同一にする：
```rust
// plugins/tauri-plugin-modules/src/ankidroid.rs
#[cfg(target_os = "android")]
pub const ANKIDROID_IDENTIFIER: &str = "org.gorakudo.entei.modules.ankidroid";

#[cfg(target_os = "android")]
pub fn init_android<R: tauri::Runtime, C: serde::de::DeserializeOwned>(

    api: &tauri::plugin::PluginApi<R, C>,

    Ok(api.register_android_plugin(ANKIDROID_IDENTIFIER, "AnkiDroidModule")?)

#[cfg(not(target_os = "android"))]
pub fn init_android<R: tauri::Runtime, C: serde::de::DeserializeOwned>(
    _app: &tauri::AppHandle<R>,
    _api: &tauri::plugin::PluginApi<R, C>,

    Ok(())
}
```

`lib.rs` のプラグインビルダーで `.setup` を接続し、プラグインハンドルを保持するとともに `invoke_handler` にコマンドを登録：
```rust

pub fn init<R: Runtime>() -> TauriPlugin<R> {
```

## 3. モジュール API エンドポイント (`plugin:modules|...`) とフロントエンド統合

### 3.1 登録される Tauri IPC コマンド
1. **`modules_ankidroid_request(action: String, version: Option<u32>, params: Option<Value>, key: Option<String>)`**:
   - AnkiConnect 互換アクション（`version`, `deckNames`, `modelNames`, `addNote`, `updateNoteFields`, `storeMediaFile` 等）をディスパッチ。
   - Android では Kotlin の `AnkiDroidModule` を `run_mobile_plugin_async` で呼び出し、`{ "result": any, "error": null }` エンベロープとして返却。
   - 非 Android では `Err("unsupported-platform")` を返却。
2. **`modules_ankidroid_check_connection()`**:
   - フロントエンドの `isAnkiNativeConnectionStatus`（`tauri-bridge.ts:126-158`）バリデータを 100% パスするよう、**全必須キーを明示設定（null の場合も `null` を出力）** して返却：
     ```json
     {
       "state": "connected",
       "endpoint": "content://com.ichi2.anki.flashcards",
       "version": 6,
       "requireApiKey": false,
       "decks": ["Default", "日本語"],
       "models": ["Basic", "DenChou"],
       "message": null,
       "errorKind": null
     }
     ```
   - 状態 `state` は `'connected' | 'unavailable' | 'permission-denied' | 'api-key-required' | 'unknown-error'` の定義域に従う。

### 3.2 フロントエンド透過ルーティング (`tauri-bridge.ts` & クライアント層)
1. **環境判定 `isAndroid()`**:
   - `tauri-bridge.ts` に `export function isAndroid(): boolean` を新設（`isTauri() && /android/i.test(navigator.userAgent)`）。
2. **クライアント側のルーティング順序（最優先評価）**:
   - Android WebView 内でも `isTauri() === true` となるため、**`isAndroid()` の判定は既存の `if (isTauri())` 分岐よりも「前（先頭）」で最優先評価する**。
   - `AnkiConnectClient.request()` および `AnkiExportClient.request()` において、`isAndroid()` の時は既存のデスクトップ用 `plugin:anki|anki_request` や `fetch()` を一切呼ばず、`invoke('plugin:modules|modules_ankidroid_request', { action, version: 6, params: params ?? {}, key: this.apiKey })` を呼び出す（`raceWithAbort(..., signal)` も維持しキャンセル安全性を担保）。
   - `ankiCheckConnectionDirect()` も `isAndroid()` 時は既存の `plugin:anki` ではなく `invoke('plugin:modules|modules_ankidroid_check_connection')` へ短絡。
   - これにより、`PlayerApp.tsx` の採掘フロー、`AnkiAppendPanel.tsx` の追記フロー、`MiningPreviewDialog.tsx` の全エクスポート処理、設定画面の接続チェックが、一切のコード改変なしに Android ネイティブへ直通する。

## 4. API 実装詳細と厳格な契約仕様

### 4.1 デッキ管理 (`DeckApi`)
`AddContentApi.deckList` プロパティを用いてデッキ一覧を抽出する（nullable な `Map<Long, String>?` を安全に受ける）。
- **`deckNames()`**: `api.deckList?.values?.toTypedArray() ?: emptyArray()`
- **`deckNamesAndIds()`**: `api.deckList?.entries?.associate { it.value to it.key } ?: emptyMap()`
- **`getDeckId(name: String)`**: `deckNamesAndIds()[name] ?: throw Exception("Deck not found: $name")`

### 4.2 ノートタイプ管理 (`ModelApi`)
`AddContentApi.getModelList(minNumFields: Int)` および `getFieldList(modelId: Long)` を使用。
- **`modelNames()`**: `api.getModelList(0)?.values?.toTypedArray() ?: emptyArray()`（引数 `0` で全件取得）。
- **`modelNamesAndIds()`**: `{ [modelName: string]: number }` のマップを返却。
- **`modelFieldNames(modelName: String)`**: ノートタイプ名から内部 `modelId` を解決し、定義されているフィールド一覧（`String[]`）を正確な順序で返却。
- **`getModelName(modelId: Long)`**:
  - `api.modelList?.get(modelId) ?: "Default"`
- **`getNoteModelId(noteId: Long)`**:
  - `AddContentApi.getNote()` の PROJECTION は `MID` を含まないため、以下の独立クエリで解決する：
  ```kotlin
  val noteUri = Uri.withAppendedPath(FlashCardsContract.Note.CONTENT_URI, noteId.toString())
  val cursor = context.contentResolver.query(noteUri, arrayOf(FlashCardsContract.Note.MID), null, null, null)
  cursor?.use {
      if (it.moveToNext()) return it.getLong(it.getColumnIndexOrThrow(FlashCardsContract.Note.MID))
  }
  return null
  ```

### 4.3 ノート追加・重複チェック (`NoteApi`)

#### ① 重複判定 (`canAddNotes`)
- モデルの第1フィールド名（`api.getFieldList(modelId)?.getOrNull(0) ?: throw Exception("Fields not found for model $modelId")`）を取得。
- 送信されたデータの第1フィールド値（素テキスト）を取り出す。
- `api.findDuplicateNotes(modelId, firstFieldText)` を呼び出し、該当ノートが存在するか確認する（※AnkiDroid 内部でクエリが安全に構築される）。
- `allowDuplicate: true` の場合は、第1フィールドが非空であれば無条件に `true`（追加可能）を返す。

#### ② 新規カード追加 (`addNote`)
- `modelId` と `deckId` を解決。
- フィールドのマップ（`Map<String, String>`）をモデルのフィールド定義配列（`api.getFieldList(modelId)`）の順序に従った配列（`String[]`）へ並び替え（未指定フィールドは `""`）。
- `tags` は `List<String>` から `Set<String>` へ変換。
- `api.addNote(modelId, deckId, fields, tags.toSet()) ?: throw Exception("Failed to add note to AnkiDroid")` を呼び出し、生成された `noteId`（`Long`）を返却。

#### ③ 既存カードの差分マージ更新 (`updateNoteFields`) 🚨 【重要・データ消失防止】
AnkiDroid の `api.updateNoteFields(noteId, fields: Array<String>)` はカードの全フィールドを**完全置換**するため、必ず以下の「読み取り → 差分マージ → 全置換」を実行する：
```kotlin
fun updateNoteFields(noteId: Long, incomingFields: Map<String, String>): Boolean {
    val modelId = getNoteModelId(noteId) ?: throw Exception("Model not found for note $noteId")
    val allFieldNames = api.getFieldList(modelId) ?: throw Exception("Fields not found for model $modelId")
    
    // 1. 既存の全フィールド値を読み取る
    val existingNote = api.getNote(noteId) ?: throw Exception("Note not found: $noteId")
    val existingFields = existingNote.getFields()
    
    // 2. モデル定義順の全フィールド配列を構築
    val mergedFields = Array(allFieldNames.size) { i ->
        val fieldName = allFieldNames[i]
        if (incomingFields.containsKey(fieldName)) {
            incomingFields[fieldName] ?: ""
        } else if (i < existingFields.size) {
            existingFields[i]
        } else {
            ""
        }
    }
    
    // 3. 安全にマージされた完全長配列で更新
    return api.updateNoteFields(noteId, mergedFields)
}
```

### 4.4 カード詳細・検索・サスペンド (`CardApi`) 🌟 【重要・10進スケール合成 cardId による完全解決】

JavaScript の `Number.MAX_SAFE_INTEGER`（`9,007,199,254,740,991` ≈ 9.0e15）を超えないよう、noteId（13桁エポックミリ秒 ≈ 1.7e12）に対して **1000 進合成（`cardId = noteId * 1000 + cardOrd`）** を採用する：
- 最大値: `1.7e12 * 1000 + 999 ≈ 1.7e15`（`Number.MAX_SAFE_INTEGER` の安全範囲に 100% 収束し、精度落ちや誤カード休止が物理的にゼロ）。
- `fun makeCardId(noteId: Long, cardOrd: Long): Long = noteId * 1000L + (cardOrd % 1000L)`
- `fun parseNoteId(cardId: Long): Long = cardId / 1000L`
- `fun parseCardOrd(cardId: Long): Int = (cardId % 1000L).toInt()` 🚨 【重要・Intキャスト】

1. **`findCards('nid:<noteId>')`**:
   - `Uri.parse("content://com.ichi2.anki.flashcards/notes/$noteId/cards")` をクエリ。
   - 各カードの `CARD_ORD` を読み取り、`makeCardId(noteId, cardOrd)` で合成カード ID 配列（`Long[]`）を生成して返却。
2. **`cardsInfo(cardIds: List<Long>)`**:
   - 各 `cardId` を `parseNoteId` と `parseCardOrd` で分解。
   - `notes/<noteId>/cards/<ord>` をクエリし、`DECK_ID` から `DeckApi.deckList` を引いて `deckName` を解決。
   - `QUESTION`, `ANSWER`, `ModelApi.getModelName(modelId)` を取得し、`AnkiCardInfo` 配列（`cardId, deckName, modelName, question, answer`）を返却（※追記パネルの Deck 列が Android でも完璧に表示される）。
3. **`suspend(cardIds: List<Long>)`**:
   - 各 `cardId` を分解して `val nid = parseNoteId(cardId)`、`val ord = parseCardOrd(cardId)`（Int型）を取得。
   - `ContentValues` に `ReviewInfo.NOTE_ID` (Long), `ReviewInfo.CARD_ORD` (Int), `ReviewInfo.SUSPEND` (`1`, Int) を設定し、`FlashCardsContract.ReviewInfo` に対し単独 update を実行。
   - 新規カード作成後の `suspendNewCards` が Android でも確実にカードを休止する。
4. **`notesInfo(noteIds: List<Long>)`**:
   - `AddContentApi.getNote(id)` で `FLDS` と `TAGS` を取得。
   - `val mid = getNoteModelId(id) ?: 0L` から `modelName = ModelApi.getModelName(mid)` と `api.getFieldList(mid)` を引いて `{ [fieldName]: { value, order } }` のマップを構成。
   - `notes/<id>/cards` をクエリし、先頭カードの `DECK_ID` から `deckList` を引いて `deckName` を解決。
   - 合成 `cardId` 配列を生成し `cards: Long[]` に格納して返却（※`noteId, modelName, deckName, fields, tags, cards` の完全オブジェクト）。

### 4.5 メディアファイル連携 (`MediaApi`) 🚨 【重要・Scoped Storage 適合】

Android 11 以降の Scoped Storage 制約下で、Entei のアプリ内一時ファイル（録音音声や動画スクショ）を AnkiDroid へ確実に引き渡す：

1. **一時ファイル書き出し**:
   - `params.data` の base64 文字列をバイナリへデコード。
   - `val mediaDir = File(context.cacheDir, "anki_media").apply { mkdirs() }`
   - 一時ファイル（例: `entei_audio_xxxxxxxxxx.webm` や `.jpg`）を作成し書き込み（0 バイト時は即座にエラー）。
2. **FileProvider URI の発行と権限供与**:
   - `FileProvider.getUriForFile(context, "${context.packageName}.anki.fileprovider", file)` で `content://` URI を発行。
   - `context.grantUriPermission("com.ichi2.anki", fileUri, Intent.FLAG_GRANT_READ_URI_PERMISSION)` を実行。
3. **ContentValues の構築（FILE_URI 必須 ＆ PREFERRED_NAME 拡張子除去・文字種制限）**:
   - `FlashCardsContract.AnkiMedia.FILE_URI` に `fileUri.toString()` を設定（必須）。
   - `preferredName`: 拡張子を除去し、`[^A-Za-z0-9_-]` を `_` に置換。3文字未満なら `"entei_media"` へフォールバック。
   - `FlashCardsContract.AnkiMedia.PREFERRED_NAME` に格納。
   - ※ AnkiDroid 側は `ContentResolver.getType(fileUri)` から MIME を引き、`MimeTypeMap` 経由で実拡張子（`.mp3`, `.jpg`, `.webm`）を付与する。
4. **ContentResolver への登録と確定ファイル名の取得**:
   - `val insertedUri = contentResolver.insert(FlashCardsContract.AnkiMedia.CONTENT_URI, contentValues)`
   - `insertedUri` が null の場合は `AnkiExportError`（`server-error`）を送出。
   - 戻り値 URI（`file://.../<確定ファイル名>`）から `File(insertedUri.path).name` で確定ファイル名を取得。
   - 返却名は **パスなし・マークアップなし・`[A-Za-z0-9._-]` のみ** の文字列としてフロントエンドへ返却。
   - `finally` ブロックで直ちに `file.delete()` および `context.revokeUriPermission("com.ichi2.anki", fileUri, Intent.FLAG_GRANT_READ_URI_PERMISSION)` を実行（リーク防止）。
5. **フロントエンドでのマークアップ組み立て**:
   - プラグイン側では HTML マークアップを組まず、生ファイル名のみを返す。
   - フロントエンド（`anki-export-client.ts` の `buildMediaMarkup`）が AnkiDroid 返却確定ファイル名を使って `[sound:確定ファイル名.webm]` や `<img src="確定ファイル名.jpg">` を組み立てる。

## 5. AnkiConnect アクション互換性マッピング表

Entei Modules が受領し、AnkiDroid Connect モジュールへ中継するアクション対応表：

| AnkiConnect アクション | 呼び出し元 | Android ネイティブでの実装方針 | 返却型 / 契約 |
|---|---|---|---|
| `version` | 接続確認・疎通 | 常に `6` を返却（`api.apiHostSpecVersion >= 2` を確認） | `6` (数値) |
| `requestPermission` | 接続確認 Step 2 | `ContextCompat.checkSelfPermission` の実判定結果を返却 | `{ "permission": "granted" / "denied", "requireApiKey": false }` |
| `deckNames` | 設定・Field Profiles | `DeckApi.deckNames()` | `string[]` |
| `deckNamesAndIds` | 設定・Field Profiles | `DeckApi.deckNamesAndIds()` | `{ [deck: string]: number }` |
| `modelNames` | 設定・Field Profiles | `ModelApi.modelNames()` | `string[]` |
| `modelNamesAndIds` | 設定・Field Profiles | `ModelApi.modelNamesAndIds()` | `{ [model: string]: number }` |
| `modelFieldNames` | 設定・Field Profiles | `ModelApi.modelFieldNames()` | `string[]` |
| `canAddNotes` | 新規カード作成前 | `NoteApi.canAddNotes()`（`allowDuplicate: true` 時は第1フィールド非空判定） | `boolean[]` |
| `addNote` | 新規カード作成 | `NoteApi.addNote()` | `number` (noteId) |
| `updateNoteFields` | 最新カード更新 | `NoteApi.updateNoteFields()`（差分マージ全置換） | `{ "noteId": number }` |
| `addTags` | カード更新・追記後 | `api.updateNoteTags()` + `api.getNote().tags` の Union 合成 | `null` |
| `storeMediaFile` | 画像・音声保存 | `MediaApi.storeMediaFile()`（FileProvider + 確定ファイル名返却） | `string` (確定ファイル名) |
| `findNotes` | 最新カード・重複・追記 | `FlashCardsContract.Note.CONTENT_URI` へのクエリ（クエリ文字列をそのまま selection に渡し、0件・null時は `[]` を返却） | `number[]` |
| `notesInfo` | カード情報取得 | `FlashCardsContract.Note` のクエリ（`noteId, modelName, deckName, fields, tags, cards` を構成） | `AnkiNoteInfo[]` |
| `cardsInfo` | 追記時のデッキ名解決 | 合成 `cardId` を分解し、`notes/<nid>/cards/<ord>` をクエリして `DECK_ID` から `deckName` を解決 | `AnkiCardInfo[]` |
| `findCards` | 新規カード休止用 | `notes/<nid>/cards` をクエリし、各カードの合成 `cardId` リストを返却 | `number[]` |
| `suspend` | 新規カード休止 | 合成 `cardId` を分解し、`FlashCardsContract.ReviewInfo` に `NOTE_ID` + `CARD_ORD` (Int) + `SUSPEND = 1` (Int) を update | `boolean` (true) |
| `apiReflect` | AnkiDroid 自動判定 | 🚨 **`{ scopes: ["actions"] }` のみを返し `actions` 配列は返さない**（フロントエンドが `Array.isArray(actions) === false` を見て確実に `ankiDroidMode = true` と判定させるため） | `{ "scopes": ["actions"] }` |

## 6. AndroidManifest.xml とセキュリティ設定

プラグイン配下（`plugins/tauri-plugin-modules/android/src/main/AndroidManifest.xml`）に以下を宣言する（※`package` 属性は指定せず `build.gradle.kts` の `namespace` で管理する）：

```xml
<manifest xmlns:android="http://schemas.android.com/apk/res/android">

    <!-- 1. AnkiDroid データベースへの読み書き権限 -->
    <uses-permission android:name="com.ichi2.anki.permission.READ_WRITE_DATABASE" />

    <!-- 2. Android 11+ パッケージ可視性 (これがないと resolveContentProvider が null になり未インストール扱いになる) -->
    <queries>
        <package android:name="com.ichi2.anki" />
    </queries>

    <application>
        <!-- 3. メディア受け渡し用 FileProvider -->
        <provider
            android:name="androidx.core.content.FileProvider"
            android:authorities="${applicationId}.anki.fileprovider"
            android:exported="false"
            android:grantUriPermissions="true">
            <meta-data
                android:name="android.support.FILE_PROVIDER_PATHS"
                android:resource="@xml/anki_file_provider_paths" />
        </provider>
    </application>
</manifest>
```

### `res/xml/anki_file_provider_paths.xml`
```xml
<?xml version="1.0" encoding="utf-8"?>
<paths>
    <!-- アプリのキャッシュ内 anki_media サブディレクトリのみ提供を許可 -->
    <cache-path name="anki_media_cache" path="anki_media/" />
</paths>
```

## 7. フェイルソフトと接続チェック設計

1. **`modules_ankidroid_check_connection` コマンドの実装**:
   - デスクトップのローカル HTTP は使わず、Kotlin の `AnkiDroidModule` を呼び出す。
   - Kotlin 側で `api.apiHostSpecVersion >= 2`、パーミッション有無、`api.deckList`、`api.getModelList(0)` の取得を順次検証し、デスクトップと同一形状の `AnkiNativeConnectionStatus`（全必須キー `message: null, errorKind: null` 完備）を返却する。
2. **AnkiDroid 未インストール / 旧バージョンの検知**:
   - `api.apiHostSpecVersion` をチェック。
   - `-1`（未インストール）または `1`（古いバージョン）の場合は、`AnkiExportError`（`code: 'network'`）として「AnkiDroid がインストールされているか確認してください（ContentProvider Spec 2 以上が必要です）」と親切にトースト通知する。
3. **権限（Permission）未許可時のフェイルソフト**:
   - `AddContentApi.READ_WRITE_PERMISSION` が未付与の場合は、アプリをクラッシュさせず「AnkiDroid へのアクセス権限がありません。設定から許可してください」とトーストで案内する。
   - ※実際の権限要求ダイアログは、後日新設する専用の「アプリオンボーディング画面」で実行する。
