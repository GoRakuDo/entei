# YT Embedded Subtitle Search

> 参考例文検索（YouGlish 的な「キーワード → YouTube の字幕から該当シーンを探して再生」）を、セルフホスト・軽量・Android 対応で実現する機能の設計ドキュメント。
>
> 状態: **設計確定（2026-08-10）・未実装**。詳細 UI のモックアップは後日描く（= このドキュメントは仕様の一次ソース）。

## 1. 目的

ユーザーが学習中に単語・フレーズの「参考例文」を見つけやすくする。入力したキーワードが **YouTube の字幕（CC・自動生成含む）** に現れる動画と、その**該当タイムスタンプ**を検索し、**YouTube Embed**（= 公式 iframe・`?start=秒`）で該当シーンから再生する。

- YouGlish は採用しない（= 日次検索上限・ストレージ削除による上限回避は ToS 違反リスクのため不可・外部依存）。
- Nadeshiko 連携は別件（= `docs/NADESHIKO_INTEGRATION.md` にて CORS 疎通確認・BYOK クライアントサイド連携として設計確定）。本ドキュメントは YouTube 字幕セルフホスト検索に特化。

## 2. 確定スペック（ユーザー確定・2026-08-10）

1. **デフォルトチャンネルリスト**を用意する（= 初期収集対象。リストの中身は後日確定）。
2. **ユーザーが設定モーダルから好きなチャンネルを追加・保存**できる（= ローカル永続・ユーザーの追加チャンネルはデフォルトリストと合算して収集対象）。
3. **UI**: サイドパネルではなく**プレイヤー枠内に SVG アイコン**を追加。押すとモーダルが開き、そこに**単語検索欄**がある。検索ボタンを押すと、その単語がある動画が **YouTube Embed で 1 本目**として表示される。**Next ボタン**を押すと 2 番目以降の候補へ YouTube Embed を差し替える。
4. **Android で軽量・高速**に動く（= 収集はバックグラウンド・検索はミリ秒・再生負荷は YouTube 側）。
5. **検索対象**: 検索時に**全チャンネルリスト（= デフォルト + ユーザー追加）の収集済み字幕**から、**動画 CC と自動字幕の両方**を含めて検索する。結果は**タイムスタンプごと**に候補となり、YouTube Embed を（1 本目 → Next → 2 本目…と）差し替えていく。
   - ※「ランダムに全チャンネルリストから」の部分の正確な解釈（= 検索結果の順序をランダムにする／対象動画をランダム抽出する）は**後日確認**（現状: 検索ヒット順をそのまま候補にし、Next で巡回）。

## 3. 採用設計（OSS 調査の結論・2026-08-10）

候補 OSS の調査結果:

| 候補 | ライセンス | 評価 |
|---|---|---|
| **yt-fts**（NotJoeMartinez） | Unlicense | 字幕→SQLite FTS5 検索の**エンジン設計**が最良の参考。`-l ja` で日本語自動生成字幕対応・API キー不要。作者は放置宣言済み（機能維持）。**Go companion が SQLite を直接読み書きできる**点が本設計と親和 |
| **Jerma-Subtitle-Search** | GPL-3.0 | 「キーワード→タイムスタンプ→**YouTube embed 再生**」の**フロント完成例**が唯一無二（lite-youtube-embed + MiniSearch・静的）。チャンネル固定設計のためそのままは使わない・**パターンのみ参考**（GPL コードの流用はしない） |
| **SubTubular**（h0lg） | MIT | 収集+全文検索の**設計図**として最良（LIFTI・キャッシュ戦略）。.NET 依存で部品移植不可 |
| **quipclipper** | MIT | 「検索→embed 再生」が完成した Web アプリ唯一の例・活発。ただし YouTube 機能は experimental・FastAPI 追加プロセスが重いため不採用 |

**採用方針**:

- **収集**: companion（EizouDendenshi・Go・127.0.0.1）が yt-dlp（既存）で字幕のみ取得（`--skip-download --write-subs --write-auto-subs --sub-langs "ja.*"`）。チャンネルリスト分を**バックグラウンドで逐次収集**（初回バッチ + 以降は差分）。
- **インデックス**: **SQLite FTS5**（= yt-fts の設計を参考・Go 標準の `modernc.org/sqlite` 等で読み書き）。検索はミリ秒・数 GB 規模でも問題なし。
- **検索 API**: companion に検索エンドポイント 1 本（例: `POST /v1/ytsearch` `{query}` → 候補リスト: 動画 ID・タイムスタンプ・字幕行・チャンネル名）。
- **再生 UI**: フロント（React）のモーダル内に **YouTube iframe embed**（`https://www.youtube.com/embed/{id}?start={秒}`）。Next で候補を差し替える（= Jerma の lite-youtube-embed パターン参考・ライセンス問題なし）。
- **チャンネル管理**: デフォルトリスト + ユーザー追加（設定モーダル・既存の SettingsTabs に EizouDen タブ等へ追加 or 別タブ）をローカル保存。

## 4. データ規模の試算（数千チャンネル前提）

| 項目 | 目安 |
|---|---|
| 字幕 1 本 | 20〜100 KB（VTT・ja 自動生成） |
| 1 万本 | ≈ 1 GB |
| 10 万本 | ≈ 5〜10 GB |
| 収集速度 | 1 本 1〜2 秒（字幕のみ）・並列 10〜20 → 1 万本で数時間・10 万本で 1〜2 日 |
| 検索速度 | FTS5 でミリ秒 |

- 収集対象の上限（= 各チャンネルの直近 N 本／全動画）は**後日確定**（推奨: 直近 100 本程度から開始し、安定後に拡張）。

## 5. 実装フェーズ案（未確定・モックアップ後に詳細化）

- **P1（基盤）**: companion に「チャンネルリスト管理（デフォルト + ユーザー追加の保存）」+「字幕収集（バックグラウンド・差分更新）」+「SQLite FTS5 インデックス」+「検索 API」。

- **P3（管理）**: 設定モーダルからのチャンネル追加・削除・収集状況（= 収集済み本数等）の表示。

## 7. ライセンス・規約上の注意

- 収集は各動画の字幕（CC/自動生成）を**ローカルに保持**する運用。YouTube の規約（字幕データの再配布はしない・学習目的の個人利用）を尊重し、**収集結果を公開・再配布しない**（= ローカルのみ・デフォルトリストも任意の公開チャンネル）。
- 参考 OSS: yt-fts（Unlicense）・SubTubular（MIT）・Jerma-Subtitle-Search（GPL-3.0・パターンのみ参考・コード流用なし）。
- YouTube Embed の利用は公式 iframe・YouTube ToS に従う（= 必要なら ToS/Google Privacy へのリンク表示）。
