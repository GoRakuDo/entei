# Audio Player 設計

## 1. 目的

M4Bオーディオブックなどの音声専用メディアを、動画プレイヤーとは別画面で再生する。操作と情報配置は YouTube Music 風とし、音声を聴きながらジャケットまたは字幕を確認できる、local-first のプレイヤーを目指す。

対象はブラウザで選択した音声ファイルと、YouTube URLから音声として再生する配信である。音声・字幕・ジャケット画像を外部へアップロードしない（YouTubeサムネイルは公開CDNの表示のみ）。再生画面は `/audio-player/` の別ルートとし、まずURL直打ちで開けるようにする。ナビ導線は後回しとする。

## 2. 現状の土台

- `apps/web/src/features/player/media-url.ts` の `AUDIO_EXTENSIONS` に `m4b` が含まれており、M4Bは受付済みである。MIMEではなく拡張子を正として音声として扱う。
- `apps/web/src/components/player/PlayerApp.tsx` には既存の audio-area がある。現在は音符アイコン・ファイル名・`<audio>`を表示し、`PlayerControls`、再生位置、速度、履歴・セッションの既存経路を共有している。
- 字幕同期やMKV処理で、ブラウザ内WASMを使う前例がある。ただし音声プレイヤーのジャケット抽出はWASM処理として設計しない。
- `docs/PROFILE.md` §10-11 に、`watch_history` のプロフィール履歴表示と `watch_sessions` のセッション詳細表示が定義されている。音声もこのlocal IndexedDB基盤へ接続する。

## 3. 画面設計

音声プレイヤーは動画プレイヤーの映像面を流用せず、音声専用画面として構成する。大画面では中央のメディア表示と下部コントロール、狭い画面では縦積みとし、再生操作を常に画面内に残す。

### 3.1 Subtitle / Cover 切替

- 画面上部またはメディア表示部に `ButtonGroup` を置き、`Subtitle` と `Cover` を排他的に切り替える。
- 選択状態は明確な選択スタイルと `aria-pressed` 相当の状態で示す。切替で再生位置・再生/一時停止状態・速度を失わない。
- `Cover` はジャケット画像を大きく表示する。YouTube再生時は `maxresdefault` サムネイルを使い、失敗時は `hqdefault` へ、さらに失敗時はタイトルと音声アイコンによる文字画面へ静かにフォールバックする。画像がない、壊れている、読み込みに失敗した場合も同様に文字表示へ戻す。
- `Subtitle` は読み込まれた字幕のリストを表示し、現在行を強調する。行を選ぶとその開始位置へシークする。字幕がない場合は、空状態としてタイトルと「字幕なし」を表示する。

### 3.2 共通情報と操作

- タイトルをジャケット/字幕表示の近くに表示する。M4Bのタイトルメタデータを優先し、ない場合はファイル名を使う。
- シークバー、経過時間、総時間を表示する。シーク後も現在の再生状態を維持し、意図しない自動再生はしない。
- 再生/一時停止に加え、`-30秒`、`-10秒`、`+10秒`、`+30秒` のスキップ操作を提供する。先頭・末尾を超えないように範囲を丸める。
- 速度操作は既存プレイヤーの速度設定・`playbackRate`経路を再利用する。速度ボタンまたは選択部から通常速度を含む既存の選択肢を変更でき、選択値は既存の音量/速度設定契約に従う。
- キーボード操作とタッチ操作の双方で、切替・シーク・速度変更を実行できる。ボタンには動作を説明するラベルを付ける。

## 4. ジャケット絵の取得

### 4.1 抽出方法

M4B選択後、ブラウザ対応の `music-metadata` を使って `File` を解析し、`metadata.common.picture` から `selectCover` でジャケット候補を選ぶ。画像のMIME typeとバイト列から画面表示用のローカル画像URLを作り、音声ファイル本体とは別に表示状態として管理する。

タイトルも同じメタデータ読込で取得し、`common.title` が空ならファイル名へフォールバックする。解析、画像形式、画像データが不正な場合は再生を止めず、Cover画面を文字表示へ戻す。

### 4.2 WASM化しない理由

`music-metadata` はブラウザの `Blob`/`File` とJavaScriptでタグと添付画像を読めるため、PCMデコードやトランスコードを必要とする処理ではなく、ジャケット抽出のためにWASM化する利点がない。

### 4.3 YouTubeサムネイル

YouTubeを音声として再生する場合、Coverは `https://i.ytimg.com/vi/{videoId}/maxresdefault.jpg` を使い、失敗時は `hqdefault.jpg` へ、さらに失敗時は文字画面へ倒す。`videoId` は視聴URLから抜き、タイトルは `jobTitle` を使う。履歴のポスター解決と同じ流用であり、新しい取得経路は作らない。

### 4.4 メモリと永続化

- 表示中の画像URLはメディア差し替え・画面破棄時に解放する。
- 生の音声ファイル、ファイルパス、オブジェクトURLは保存しない。
- 音声履歴のポスターとして使う場合は、再読み込み後も参照できるlocal-onlyの画像表現（画像データの小さな永続化または既存履歴の画像参照方式）に変換する。短命なBlob URLだけを `posterUrl` として保存してはならない。
- 画像の抽出・永続化に失敗した場合も、履歴レコード自体はタイトルカードとして残せるようにする。

## 5. 履歴・セッション

### 5.1 `watch_history`

既存の `watch_history` に `source: 'audio'` を追加する方針とする。既存の `local`（動画等）と `youtube` の意味は変更しない。

- `mediaId` は既存のローカルメディア識別方式を使い、ファイル名だけをIDにしない。
- `title` はM4Bメタデータのタイトル、なければファイル名を記録する。
- `episode` は音声作品に該当情報がない場合 `null` とする。
- `source` は `audio` とし、プロフィールのコンテンツ履歴では音声作品として表示できるようにする。
- `poster` はM4Bから抽出したジャケット絵を使う。画像なし・抽出失敗時は `posterStatus: 'none'` とし、タイトル/文字カードへフォールバックする。
- 記録タイミングは既存契約どおり、開いた瞬間ではなく、再生開始から60秒または全体の5%到達の早い方とする。失敗しても再生は妨げない。
- YouTube音声再生は既存 `source: 'youtube'` を流用する。`mediaId` は `youtube:{videoId}`、タイトルは `jobTitle`、ポスターは上記サムネイルとし、新しい履歴種別は作らない。
- プロフィールのコンテンツ履歴では音声を独立したリスニング段に並べる。デスクトップ5列・モバイル2列の四角Coverグリッドとし、既存のアニメ・ドラマ段やYouTube段とは分ける。

### 5.2 `watch_sessions`

音声でも既存の `watch_sessions` を流用する。新しい音声専用セッションストアは作らない。

- プレイヤーへ入った時にセッションを開始し、離脱・タブ終了・リフレッシュ・ファイル差し替えで確定する。
- 一時停止、巻き戻し、速度変更は同じセッション内の操作とする。
- `mediaId`、開始/終了時刻、実再生時間、`episode`、採掘文の既存フィールドをそのまま使う。字幕が読み込まれている音声では、既存の採掘経路も同じセッションへ関連付ける。
- プロフィールの履歴カードから開くDrawerでは、動画と同じくセッション回数・合計時間・各回の詳細を表示する。

## 6. スコープ外

- 音声のトランスコード・形式統一（オリジナルパススルーとし、形式ごとの正しいContent-Type配信を条件とする）
- Freenet への公開・同期
- DRM付きM4Bの解析・再生・保護解除
- 音声ファイルの外部アップロード、サーバー側のジャケット保管
- 動画プレイヤー画面への音声UIの混在

## 7. 実装順

1. **doc** — 本設計を正とし、画面・抽出・履歴の契約を固定する。
2. **音声取得** — companionのYouTube音声専用取得（高音質パススルー＋形式ごとの正しいContent-Type）と `<audio>` での実再生確認。
3. **絵抜き** — `music-metadata` のブラウザAPIでM4Bのタイトルとジャケットを読み、画像なし/解析失敗時の文字フォールバックを確認する。
4. **画面** — `/audio-player/` の音声専用画面、Subtitle/Cover `ButtonGroup`、字幕リスト、タイトル、シーク、±10/30秒、速度操作を実装する。
5. **履歴** — `watch_history` の `audio` source、ジャケットポスター、既存 `watch_sessions` の記録とプロフィール表示を接続する。YouTube音声は `source: 'youtube'` 流用＋サムネイルCoverで同段階に含める。プロフィールには独立リスニング段（デスクトップ5列・モバイル2列）を置く。

各段階で音声再生そのものを壊さず、次段階へ進む前に失敗時フォールバックとlocal-only境界を確認する。
